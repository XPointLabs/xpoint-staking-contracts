# DeepSession: Токеномика и распределение XPNT (RU)

Обновлено: 2026-06-18.

Документ описывает архитектуру, модель распределения и ролевую структуру токена XPNT в экосистеме DeepSession.

---

## 1) Общая информация о токене

### Базовые характеристики

| Параметр | Значение |
|---|---|
| **Название** | XPoint |
| **Тикер** | XPNT |
| **Общее предложение (Max Supply)** | 240,000,000 XPNT |
| **Десятичность** | 9 |
| **Тип** | ERC-20 (L1), ERC-20 upgradeable proxy (L2 Arbitrum) |
| **Статус** | Минтировано полностью при развёртывании |

### Сети развёртывания

- **L1 (Ethereum mainnet)**: `0xc890b3Dac12a78B3449219a988f69CC25683575f` (не upgradeable)
- **L2 (Arbitrum One)**: `0x63B2cdb8B0d8774F1Fdca91D24803698582a079F` (upgradeable proxy)

### Принцип работы L1/L2

Токен использует Arbitrum Custom Gateway для бридживания:
- Все 240M XPNT минтированы в L1 и заблокированы в gateway.
- При бридже пользователь отправляет токены в L1 gateway → получает эквивалент в L2.
- Отправка из L2 в L1 работает через L2 gateway → пользователь получает оригинальные токены из L1 escrow.

## 2) Текущее распределение токенов (По факту развёртывания)

Основано на скрипте развёртывания `scripts/deploy-common.js`:

```
Общее предложение:              240,000,000 XPNT  (100%)
├── Reward Rate Pool (вознаграждения):  40,000,000 XPNT  (16.7%)
└── Оставшиеся для распределения:      200,000,000 XPNT  (83.3%)
```

### 2.1 Reward Rate Pool (40,000,000 XPNT)

**Назначение**: Долгосрочный резерв для выплаты вознаграждений операторам сервис-нод.

**Механика**:
- Инициализируется с 40M XPNT при развёртывании.
- Работает на принципе простой ставки 15.1% годовых (приближение к 14% реальной отдачи).
- Постепенно высвобождает токены в ServiceNodeRewards через регулярный `checkpoint` каждые 5 минут (в UAT) или при ручном вызове (в продакшене).
- При росте числа сервис-нод и их требований к ликвидности может дополняться из подписочной выручки (40% платежей SubscriptionManager).

**Почему 40M?** Это буфер на 6-12 месяцев при умеренной активности нод. Расчёт:
```
Ежегодный выпуск ≈ 40M × 14% = 5.6M XPNT/год
Ежемесячный выпуск ≈ 467K XPNT/месяц
```

### 3.2 Обоснование каждой категории

#### 1. Staking Rewards & Operations Pool (35%)

**Объём**: 84,000,000 XPNT

**Назначение**: Стимулирование децентрализованной безопасности и долгосрочной устойчивости сети.

**Компоненты**:
- **Reward Rate Pool** (40M): Структурированное высвобождение для ежедневных выплат операторам.
- **ServiceNodeRewards операционный буфер** (44M): Готовая ликвидность для покрытия выплат на первые 12-18 месяцев без ожидания checkpoint/ежемесячных высвобождений из пула.

**Механика вознаграждения**:
- Оператор сервис-ноды пополняет минимум 20,000 XPNT (настраивается governance).
- За каждый день активности получает вознаграждение пропорционально доле в стейке.
- Вознаграждение выплачивается при соответствии BLS-подписям и требованиям uptime.

**Сравнение с конкурентами**:
- Lido: 32% токенов для validator rewards (больше, т.к. модель заимствования).
- Eigenlayer: 50% для стейкинга (более высокая, т.к. restaking поддерживает несколько сетей).
- DeepSession 35% — сбалансировано для привлечения операторов без чрезмерной инфляции.

## 5) Механика выплаты вознаграждений

### 5.1 Цикл жизни вознаграждения оператора сервис-ноды

```
[Оператор вносит 20,000 XPNT]
         ↓
[Регистрация в ServiceNodeRewards (addBLSPublicKey)]
         ↓
[Backend проецирует ежедневное вознаграждение на основе rewardRate()]
         ↓
[Каждые 5 минут (UAT) / редко (mainnet): checkpoint выпускает токены из пула]
         ↓
[Токены накапливаются в ServiceNodeRewards.recipients[address].rewards]
         ↓
[Оператор подписывает BLS-сообщение off-chain через backend]
         ↓
[Оператор вызывает claimRewards с подписью и размером]
         ↓
[ServiceNodeRewards выплачивает оператору XPNT]
```

### 5.2 Кто может быть оператором?

- **Требование**: Любой адрес с 20,000+ XPNT (изменяется governance).
- **Требование**: BLS public key + подпись (доказательство владения private key).
- **Требование**: Поддерживаемая инфраструктура (ноды, постоянное подключение).
- **Ограничение**: Макс 4 ноды на одного основного контрибьютора (предотвращает монополию стейка).

### 5.3 Как вознаграждения масштабируются?

При 100 нодах × 20,000 XPNT = 2,000,000 XPNT в стейке:
```
rewardRate() = 2,000,000 × 15.1% ÷ 365 дней = ~8,219 XPNT/день
На оператора: 8,219 ÷ 100 = ~82 XPNT/день ≈ 2,460 XPNT/месяц (~12% APY)
```

При 1,000 нодах × 20,000 XPNT = 20,000,000 XPNT в стейке:
```
rewardRate() = 20,000,000 × 15.1% ÷ 365 дней = ~82,192 XPNT/день
На оператора: 82,192 ÷ 1,000 = ~82 XPNT/день (такой же процент, новое масштабирование)
```

Вознаграждение на оператора остаётся пропорциональным (инфляция распределяется равномерно).

## 6) Экономические стимулы и защита от атак

### 6.1 Защита от whale dominance

1. **Максимум стейка на операто́ра**: Один адрес может иметь макс 4 сервис-ноды, каждая по 20K XPNT = 80K XPNT.
2. **Квадратичное голосование**: В будущих governance-решениях использовать sqrt(stake) вместо stake.
3. **Лимиты claim**: За 12 часов можно вывести максимум 1,000,000 XPNT (защита от быстрого слива).

### 6.2 Защита от инфляции

- **Фиксированное общее предложение**: 240M XPNT, никогда не увеличится.
- **Простой выпуск**: 15.1% годовых от пула, не экспоненциальный.
- **Наделение новой ликвидностью**: При выходе ноды её 20K XPNT уходит в исходного стейкера, не сжигаются.

### 6.3 Ликвидационный налог (при выходе ноды)

При выходе ноды стейк распределяется:
- **Оператору**: 99.8% (основная часть)
- **Ликвидатору** (кто инициировал выход): 0.2% (стимул мониторить сеть)
- **Пулу вознаграждений**: 0% (оставляется в пуле для ликвидности)

Это предотвращает быстрые выходы и стимулирует долгосрочное участие.

## 8) Управление и governance

### 8.1 Фазы управления

**Фаза 1: Централизованное управление (месяцы 0-12)**
- Команда DeepSession контролирует обновления контрактов (proxy admin).
- Параметры (staking requirement, reward rate) устанавливаются через owner-функции.

**Фаза 2: Переход к DAO (месяцы 12-24)**
- Развёртывание Governance токена (или использование XPNT для голосования).
- Multisig 3/5 админ для экстренных решений.
- Общественные голосования на основные параметры.

**Фаза 3: Полная децентрализация (месяцы 24+)**
- Proxy admin передаётся Governance DAO.
- Все параметры изменяются только через vote.
- Полная прозрачность через чаин-события.

## 9) Риски и смягчение

### 9.1 Инфляционный риск

**Риск**: 15.1% годового выпуска может быть слишком агрессивным.

**Смягчение**:
- Постоянное мониторирование соотношения TVL к новому выпуску.
- Возможность понижения % через governance vote.
- Резервный пул для поддержки цены при необходимости.

### 9.2 Скупка whale-ами

**Риск**: Крупные игроки могут скупить много нод и доминировать в сети.

**Смигчение**:
- Лимит 4 ноды на адрес.
- Квадратичное голосование при governance.
- Механизмы liquidation за невыполнение обязательств.

### 9.3 Regulatory неопределённость

**Риск**: Изменение регуляций может ограничить стейкинг или определить токен как ценную бумагу.

**Смигчение**:
- Консультация с юристами перед каждым раундом финансирования.
- Документирование XPNT как служебного токена (utility), не ценной бумаги.
- Географические ограничения (no US sales без SEC approval) на начальной фазе.

### 9.4 Технический риск (smart contract bug)

**Риск**: Уязвимость в контрактах может привести к потере токенов.

**Смигчение**:
- Обязательный security audit до mainnet (Certik, Trail of Bits).
- Страхование (Nexus Mutual) для стейкеров.
- Постепенный запуск с лимитами (hardcap на TVL).
